# AGENTS.md

Nintendo Switch homebrew (Atmosphere) built with libnx via devkitPro. C project. It is a browser-based file manager that runs an HTTP server on the Switch so a PC browser can browse the SD card. It is packaged as an **Atmosphere sysmodule** (runs in the background, auto-starts at boot); a dev build also exists as a plain NRO for hbmenu testing.

The current tree was **refactored from two monolithic files** (`http_server.c` ~827 lines, `main.c`) into small single-responsibility modules. Behavior (routes, JSON format, headers, statuses, port) is byte-identical to the original. See `source/` layout below.

HTTP routes (server port `8080`, defined once in `config.h`):

- `GET /` — web UI (served from `web/index.html`, auto-generated into `$(BUILD)/index_html.h` at build time)
- `GET /css/styles.css`, `GET /js/*.js` — embedded web assets (see `static_assets` in `http_server.c`); `text/css` / `text/javascript`
- `GET /api?path=...` — JSON directory listing. When `path=` is omitted, uses the configured `start_path` from `minfs.ini` (default `/`).
- `GET /download?path=...` — streams a file (download). No upload/delete/Range yet.
- `GET /img?path=...` — serves an image inline (`image/*` by extension, no `Content-Disposition`) for the UI thumbnails. Only recognized image extensions; anything else → 415.
- `GET /video?path=...` — streams a video inline (`video/*` by extension, no `Content-Disposition`) for the gallery player in the web UI. Only recognized video extensions; anything else → 415. Supports single-byte-range requests: `206 Partial Content` with `Content-Range` for `a-b`/`a-`/`-N` forms (clamped to file size), `416 Range Not Satisfiable` for unsatisfiable ranges, and malformed/multi-range headers are ignored (full 200). `Accept-Ranges: bytes` is advertised on video (and img) responses. Note: `If-Range` is ignored (no validators are sent). `Range` is only honored on `/video`, not `/img` or `/download`.

## Build

- Toolchain: devkitPro at `C:\devkitPro`. `make` requires the devkitPro MSYS2 toolchain (`aarch64-none-elf-gcc`, `switch_rules`, `npdmtool`, `build_pfs0`) — not available in stock PowerShell. Verified working from PowerShell/this agent via a non-interactive login shell:
  `& "C:\devkitPro\msys2\usr\bin\bash.exe" -lc "make"`
  (MSYS2 bash inherits the current directory from PowerShell — run it from the repo root, no `cd` needed.) Clean with `make clean`.
- The MSYS2 login profile sets `DEVKITPRO`; the Makefile hard-errors if it's unset.
- Two build modes (separate object dirs `build/` and `build_nro/`) plus a logging toggle:
    - `make` (default) → **sysmodule**: `minFS.nsp` (ExeFS PFS0 with `main`+`main.npdm`) at repo root. Compiled with `-DSYSMODULE`.
    - `make ENABLE_LOGGING=1` → same sysmodule but with file logging enabled (defines `ENABLE_LOGGING`). Sysmodule builds default to logging off; the NRO to console.
    - `make nro` → **dev NRO**: `minFS.nro` (console UI, runs from hbmenu). No `-DSYSMODULE`.
- Each mode links its **own** ELF intermediate at the repo root (`minFS-sysmodule.elf` for the sysmodule from `build/`, `minFS-nro.elf` for the NRO from `build_nro/`) via `MODE_ELF` in the Makefile, so a final can never be linked from the wrong object dir, even when switching modes without a clean. (`minFS.elf` was the old shared intermediate — no longer produced.) Note that `switch_rules`' `%.nso: %.elf` / `%.nro: %.elf` pattern rules would prepend the shared `$(OUTPUT).elf` as `$<` even when `MODE_ELF` is listed explicitly — the `.nso`/`.nro` rules in the Makefile therefore carry their **own recipes** (`elf2nso`/`elf2nro`, kept in sync with `switch_rules`) to pin the conversion input to `MODE_ELF`. Don't reintroduce a recipe-less final rule, or the build falls back to linking/deleting a phony `minFS.elf` intermediate every time.
- `ENABLE_LOGGING` is the only Makefile variable needed by the build; it's passed via `-D` in `CFLAGS`. Logging behavior per configuration is centralized in `log.h`.
- `minFS.json` (NPDM config) drives the sysmodule build; the Makefile autodetects `<TARGET>.json` when present. Title ID: `420000000007E5AC` — change in `minFS.json` (and the Ultrahand package paths, plus `LOG_FLAG_PATH` in `config.h`) if a different ID is wanted.
- `source/` is auto-globbed by the Makefile via `$(wildcard source/*.c)`; adding a new `.c` needs no Makefile edits)Skip. All new modules (below) live flat under `source/`.

## Logging (`config.h`, `log.{c,h}`)

- `config.h` holds the shared constants: `SERVER_PORT` (8080, build-time default), `LOG_FILE_PATH` (`sdmc:/switch/minFS.log`), `LOG_FLAG_PATH` (`sdmc:/atmosphere/contents/<TID>/flags/logging.flag`), `CONFIG_FILE_PATH` (`sdmc:/switch/minfs.ini`), `NOTIFY_DIR_PATH` (`sdmc:/config/ultrahand/notifications`), socket/poll timings, inner-heap size. It is included by `main.c`, `http_server.c`, `log.c`, `path_util.c`, `config_file.c`, `notify.c`.
- Two entry points, `log_debug` and `log_file`:
    - **Sysmodule**: `log_debug` and `log_file` both write to `LOG_FILE_PATH` (reopen+append per call, so the log survives without an open fd across the module's life). Writing is runtime-gated: `ENABLE_LOGGING` forces it on; otherwise it's on iff `LOG_FLAG_PATH` exists (checked per call via `stat`, so the Ultrahand `[Logging]` toggle applies instantly — no rebuild or reboot). A startup line records the server IP.
    - **NRO**: `log_debug` -> `vprintf` to console, `log_file` is a no-op (file logging is a sysmodule-only feature; the runtime flag check is compiled out).
- **Timestamps**: Both entry points prepend `[YYYY-MM-DD HH:MM:SS]` (UTC) to every log line via `log_timestamp()`, which calls `clock_gettime(CLOCK_REALTIME)` + `gmtime_r`. If the time service is unavailable, the timestamp is silently omitted (the message still logs, just without a prefix).
- The public log entry points were renamed in the refactor: old `log_to_file` → `log_file`, old `debug_printf` → `log_debug`. Call sites use `log_debug` for request noise and `log_file` for persistent events (startup, listener death, errors). Keep `(void)sent;` style casts where a value is only conditionally used, so `-Wall` stays clean under every config.

## Architecture (source/)

- `config.h` — shared constants (default port, log/flag/config/notify paths, timings, heap size). Single source of truth; keep socket/port values in sync there, not scattered across files.
- `main.c` — dual entry point:
    - Under `-DSYSMODULE`: sysmodule init hooks (`__nx_applet_type = AppletType_None`, `__nx_time_service_type = TimeServiceType_System`, `__libnx_initheap` 2MB heap, `__appInit`/`__appExit`), `socketInitialize` with `BsdServiceType_System`, `nifmInitialize(NifmServiceType_System)`, `timeInitialize()` + `__libnx_init_time()` (sysmodules must use the `:s` services; `__libnx_init_time` captures the boot wall-clock so `clock_gettime(CLOCK_REALTIME)` works — the default libnx `__appInit` normally does this, but a custom override must call it explicitly, otherwise timestamps read as uptime `1970-01-02`), and `http_server_init`. The main loop alternates `http_server_poll()` + `svcSleepThread(5ms)` forever, re-parsing the IP each pass.
    - Otherwise: old hbmenu runtime (console, pad, `+` quits).
- `http_server.{c,h}` — the HTTP server core: socket setup, per-poll single-client accept, request dispatch to the route handlers, file streaming (`send_file_ex` with the `416`/`206` range branch, `Content-Disposition` for `/download`). Listener is `O_NONBLOCK`; one client connection handled per poll. `http_server_rebind()` closes and re-inits the socket so a dropped network doesn't permanently kill the server. `http_server_init()` calls `server_config_reload()` and binds `server_config_get()->port`.
- `config_file.{c,h}` — runtime config: reads `CONFIG_FILE_PATH` (`sdmc:/switch/minfs.ini`, `[server] port=N`, `start_path=sdmc:/switch/`) into a `ServerConfig`. `server_config_reload()` re-reads the file (missing/invalid port falls back to `SERVER_PORT`; missing/invalid `start_path` falls back to `/`). The `start_path` value is converted from an SD path to an internal logical path via `fs_to_logical_path` (a leading `sdmc:` is stripped, then normalized) — the web UI opens this folder on load. `server_config_get()` exposes it. The socket bind in `http_server.c` and the startup/log lines in `main.c` use the runtime port instead of the compile-time constant.
- `notify.{c,h}` — Ultrahand integration: on successful sysmodule start, `notify_ultrahand_start(ip, port)` writes a `minFS-<timestamp>.notify` JSON into `NOTIFY_DIR_PATH` (`sdmc:/config/ultrahand/notifications`) so Ultrahand toasts `http://<ip>:<port>`. If Ultrahand isn't installed the `fopen` simply fails — harmless. NRO build never calls it.
- `http_request.{c,h}` — parses a raw request buffer into an `HttpRequest` (method, target, optional `Range` header). `Range` (`bytes=a-b` / `a-` / `-N`) is parsed into an `HttpRange` `{present,valid,suffix,start,end}` (`end=-1` = open range); `send_file_ex` in `http_server.c` interprets it. The target is only decoded/normalized later in `handle_client` via `path_from_query`.
- `path_util.{c,h}` — path helpers shared by `http_request.c` (percent-decode) and `fs_list.c`/`http_server.c` (normalize): `path_percent_decode`, `path_normalize`, `path_basename`, `path_parent_dir`, `logical_to_fs_path` (maps client `/...` to `sdmc:/...` in sysmodule builds; no-op in NRO), and its inverse `fs_to_logical_path` (strips a leading `sdmc:` and normalizes, used by `config_file.c` for `start_path`). `path_from_query` returns 1 when the query contained a `path=` param.
- `mime.{c,h}` — `mime_for_image` / `mime_for_video` extension→content-type lookups.
- `fs_list.{c,h}` — directory listings via libc `opendir`/`stat`, serialized to JSON (dirs first, then name).
- `index_html.h` / `styles_css.h` / `app_js.h` / `state_js.h` / `utils_js.h` / `ui_js.h` / `viewer_js.h` / `events_js.h` — web assets as C string literals, auto-generated at build time (`Makefile` `gen_header`, matching `WEB_ASSETS_H`). `web/index.html` → `index_html`, `web/css/styles.css` → `styles_css`, each `web/js/*.js` → `<stem>_js`. Assets are served from the `static_assets` table in `http_server.c`; any new asset must be added to both `WEB_ASSETS_H`/`gen_header` rules and the table (plus the `<link>`/`<script>` in the HTML).
- `web/index.html` — the UI markup only (no inline CSS/JS). CSS is one file `web/css/styles.css` grouped by component (base, header/crumbs, table, thumbnails, `.dl`, `#err`, `#foot`, viewer) with the palette/spacing/timings as `:root` custom properties (`--accent`, `--bg-raised`, `--pad-x`, `--t`, ...). JS is an ES-module tree under `web/js/`: `app.js` (entry: `initViewer(); initEvents(); load()`) → `ui.js` (DOM refs, render/thumbFor/load), `viewer.js` (media viewer + its events), `events.js` (document click delegation), `utils.js` (esc/fmt/join/crumbs), `state.js` (shared `state` + type helpers) — no globals; a single exported `state` object holds `cur`, `media`, `mediaIndex` (imported by `ui`, `viewer`, `events`). Looked up by JS: ids `crumbs`, `fs`, `list`, `err`, `foot`, `viewer`, `viewer-img`, `viewer-video`, classes `v-close`/`v-prev`/`v-next`/`v-counter`. The listing error banner (`#err`) gets a `.gohome` link back to root (`load("/")`) — handled in the `events.js` click delegation. Note: a plain `<a href="/">` would NOT work here, it would reload into the configured `start_path` again.
- `log.{c,h}` — logging as above.

## Gotchas

- Filesystem is plain libc. In hbmenu mode `/` = the SD root; **in sysmodule mode `/` is _not_ the SD root** (SD mounts at `sdmc:`), so `fs_list.c`/`http_server.c` map normalized client paths to `sdmc:/...` before `opendir`/`stat`/`fopen` (root `/` → `sdmc:/`). The mapping is done by `logical_to_fs_path` in `path_util.c` and is compiled out in NRO mode.
- Client-supplied paths are `percent_decode`d and clamped to `/` via `normalize_path` before touching the FS. Keep that ordering: decode first, then normalize. Control bytes (`0x00-0x1F`, `0x7F`), including percent-encoded `%0d`/`%0a`/`%00`, are dropped during decode/normalize so they can never reach the filesystem or a response header; the `/download` `Content-Disposition` filename additionally percent-encodes `"` and `\`.
- Accepted client sockets are **explicitly forced back to blocking** (`fcntl(cfd, F_SETFL, flags & ~O_NONBLOCK)`) because accepted sockets inherit the listener's non-blocking flag — without this, `recv`/`send` fail with `EAGAIN` (bug history: instant `NS_ERROR_NET_PARTIAL_TRANSFER` on downloads). `send_all` also retries `EAGAIN/EWOULDBLOCK`, and `SIGPIPE` is ignored (`signal(SIGPIPE, SIG_IGN)`) so a dropped client can't kill the process.
- `web/` assets are embedded verbatim: the Makefile `gen_header` rule runs `sed` that escapes `\` and `"` per line and preserves line breaks as `\n`, so any valid HTML/CSS/JS is safe (double-quoted attributes, backslashes, multi-line JS, template literals). The served pages are byte-identical to the files. There is deliberately no `%`-style templating; static UI only. These are build-time embeds — nothing under `web/` is read from disk at runtime. Every asset must appear in all three places: the `<link>`/`<script>` in the HTML, the Makefile `WEB_ASSETS_H`/`gen_header` rules, and the `static_assets` table in `http_server.c`. When editing, keep colors/spacing in the `:root` variables (don't hardcode values like `#8ab4f8`), keep JS module-scoped (no globals; use the `state` object), and don't change existing ids/classes or the generated DOM.
- Downloads stream synchronously in the single-threaded loop: during a transfer nothing else is served and console pads aren't polled.
- `SERVER_PORT` is defined once in `config.h` (8080). Do not redefine it in `main.c`/`http_server.c`. It is the default only — the effective port is read at init from `CONFIG_FILE_PATH` (`[server] port=N`) by `config_file.c`.
- `minFS.json`: `main_thread_stack_size` is `0x20000` (128KB) because `http_server.c`/`http_request.c` stack buffers (a `HttpRequest.raw[8192]` plus 64KB send chunks) are large — don't shrink it.
- No tests, linter, or formatter.

## Ultrahand package (`ultrahand/minFS/`)

- The Ultrahand client package lives in `ultrahand/minFS/` (`package.ini`, TID `420000000007E5AC`). Ultrahand installs a **copy** to `/switch/.packages/minFS/` at install time — editing `package.ini` here does NOT update the Switch until the package is reinstalled. `toolbox.json` is **not** part of the Ultrahand package: it is the sysmodule's toolbox opt-in config (`name`/`tid`/`requires_reboot`, tracked at the repo root) and lives on the SD card at `/atmosphere/contents/420000000007E5AC/toolbox.json` — in the module's own contents slot alongside `main.nsp` and `flags/`, not under `sdmc:/switch/.packages/`.
- Selector sections (`[*...]`) must use `;mode=option`, **not** `;mode=slot`: in Ultrahand's `SelectionOverlay`, selection lists are only built for `option`/default/toggle modes, so `;mode=slot` renders an empty list ("Selection is empty"). Use `list_source '(a, b, c)'` + `set-ini-val … {list_source(*)}` + a quoted `set-footer '{list_source(*)}'`.
- `{list_source(*)}` resolves to `null` when no item is selected. Do NOT let a selector `set-ini-val` its value straight into a live config with nothing to guard it: the broken `;mode=slot` setup once wrote `port=null` into `sdmc:/switch/minfs.ini`, which is what made `[Status]`'s `Port` show "Not available". Server-side, an invalid/corrupt `port` in `config_file.c` falls back to `SERVER_PORT` (8080), so the HTTP server still is reachable.
- Avoid `{if_null(...)}` in package rows (`[Status]`, `notify-now`): behavior varies across Ultrahand versions, and a value that resolves to `null` renders as "Not available". Read the value directly (`{ini_file(server,port)}`) and guarantee it via `set-ini-val` in the install sections instead.
